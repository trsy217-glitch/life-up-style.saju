# LIFE-UP STYLE — 결제 포함 전체 한 벌

잘사는 사주로 업그레이드하는 앱 · Style up life app

**지금은 무료 공개 기간으로 켜져 있습니다.** 잠긴 곳을 누르면 결제 없이
바로 열립니다. 토스페이먼츠 연동과 법정 고지 문서는 전부 들어 있고,
**설정 한 줄만 바꾸면 결제가 살아납니다.**

`_source/` 만 빼고 **그대로 저장소 맨 위(루트)에 올리시면** 됩니다.

---

# 0. 요금을 받기 시작하실 때

`index.html` 에서 이 한 줄만 바꾸시면 됩니다.

```js
FREE_UNLOCK: true,   →   FREE_UNLOCK: false,
```

`true` 인 동안은 "이어서 보기 (무료 공개 중)" 가 뜨고 누르면 바로 열립니다.
`false` 로 바꾸면 같은 자리에서 구매 조건 확인 창이 뜨고 토스 결제로 이어집니다.
가격·문서·서버 승인은 이미 다 붙어 있으니 **다른 것은 건드리지 않으셔도 됩니다.**

(결제를 받으실 때는 2번의 토스 키도 같이 넣으셔야 합니다.)

## 잠긴 자리가 어떻게 보이나

"여기서부터 잠겨 있습니다" 로 막아 세우지 않습니다.
**남은 글을 한 페이지쯤 흐리게 깔고** 그 아래에 버튼을 둡니다.
글의 모양과 길이가 눈에 들어와야 "뭐라고 써 있나" 하는 마음이 생깁니다.

> **블러는 보기 위한 장치이지 자물쇠가 아닙니다.** 풀이는 전부 브라우저에서
> 계산되므로 개발자도구를 열면 읽을 수 있습니다. 이건 블러 때문이 아니라
> 자족형 한 파일 구조 자체가 그렇습니다 — 예전 맛보기 방식도 마찬가지였습니다.
> 정말로 가리시려면 풀이 생성을 서버로 옮겨야 하는데, 지금 단계에서는
> 그 비용이 얻는 것보다 큽니다.

# 3. 결제가 어떻게 도는가

```
① 사용자가 "풀이 전부 열기" 누름
② 구매 조건 확인 창 — 상품·금액·청약철회 제한을 보여주고 동의 체크
③ 토스 결제창 → 카드 결제
④ /success.html 로 돌아옴 (paymentKey, orderId, amount 를 들고)
⑤ /api/confirm 에 승인 요청  ← 여기서만 진짜 승인이 난다
⑥ 서버가 토스에 승인 → 성공하면 브라우저에 열림 표시
⑦ 앱으로 돌아가면 열려 있음
```

## 왜 서버를 거치는가

브라우저가 "결제했다"고 말하는 것만 믿으면 **누구나 콘솔 한 줄로 전부 열 수 있습니다.**
그래서 승인은 `api/confirm.js` 에서만 합니다. 두 번 막습니다.

1. **주문번호에 상품 코드를 심어** 둡니다 (`LUS-all-...`, `LUS-gh-...`).
   서버가 이걸 읽어 "이 주문은 4,900원이어야 한다"를 스스로 정하고,
   브라우저가 보낸 금액과 다르면 거절합니다.
2. 토스 승인 API 가 실제 결제 금액과 또 한 번 대조합니다.

실제로 금액을 100원으로 바꿔 보내는 등 11가지 공격을 넣어 전부 막히는 것을
확인했습니다 (`_source/api-test.mjs`).

> **가격을 바꾸실 때는 두 곳을 같이 고치셔야 합니다.**
> `_source/pay.js` 의 `PRODUCT` 와 `api/confirm.js` 의 `PRICE`.
> 어긋나면 결제가 전부 거절됩니다.

## 열람 기록이 남는 곳

회원가입이 없는 구조라 **그 기기의 브라우저에만** 남습니다
(`localStorage` 의 `lifeup.paid.v1`).

- 기기를 바꾸면 다시 열어야 합니다
- 브라우저 데이터를 지우면 함께 지워집니다

이 점은 **결제 전 동의 창·약관·환불 안내 세 곳에 모두 적어 두었습니다.**
결제 완료 화면에도 "주문번호를 저장해 두시라"고 안내합니다.

나중에 회원 기능을 붙이시면 이 제약이 사라집니다. 지금은 서버에
이용자 정보를 두지 않는 쪽을 택한 결과입니다.

# 4. 법에서 요구하는 것 — 넣어 둔 것들

전자상거래법·개인정보보호법에서 디지털 콘텐츠를 파는 사업자에게 요구하는
항목입니다. 표시 자리까지 맞춰 두었으니 **내용만 채우시면** 됩니다.

| 요구 사항 | 어디에 |
|---|---|
| 사업자 정보 표시 (상호·대표자·사업자번호·통신판매업 신고번호·주소·연락처) | `terms.html` 12조 · `refund.html` 11조 |
| **결제 전 구매 조건 고지와 동의** | 결제 창 (동의 안 하면 버튼이 안 눌립니다) |
| 재화의 내용·가격·제공 시기 | 결제 창 · `refund.html` 1~4조 |
| **청약철회 제한 사실의 사전 고지** | 결제 창 · `terms.html` 5조 · `refund.html` 6조 |
| 청약철회 기간과 방법 | `refund.html` 5·7조 |
| 환불 처리 기간 | `refund.html` 8조 |
| 결제 수단과 영수증 | `refund.html` 3조 · 결제 완료 화면 |
| 분쟁 해결 절차와 기관 | `terms.html` 11조 · `refund.html` 10조 |
| 개인정보 수집·이용·보관·파기 | `privacy.html` 1~4조 |
| 개인정보보호책임자 | `privacy.html` 11조 |
| 만 14세 미만 제한 | `terms.html` 3조 · `privacy.html` 9조 |
| 처리위탁 (토스·호스팅) | `privacy.html` 6조 |

**결제 창의 동의 절차가 핵심입니다.** 디지털 콘텐츠는 "열어보면 환불이 어렵다"를
결제 **전에** 보여주고 동의를 받아야 나중에 분쟁이 생겼을 때 설 자리가 있습니다.
동의 체크를 하지 않으면 결제 버튼이 눌리지 않게 막아 두었습니다.

> 두 문서는 바로 쓰실 수 있게 만든 초안입니다.
> 결제를 받는 서비스이니, 여시기 전에 한 번은 전문가에게 확인받으시길 권합니다.

# 5. 올린 뒤 테스트 순서

**토스 테스트 키로 먼저 해 보세요.** 실제 돈이 나가지 않습니다.

1. `test_ck_` 를 `index.html` 에, `test_sk_` 를 환경변수에 넣고 Redeploy
2. 사이트 열기 → 생년월일 입력 → **금전** 갈래 → 잠금 확인
3. "풀이 전부 열기" → 동의 창에 **4,900원** 이 맞게 뜨는지
4. 동의 체크 → 결제 → 토스 테스트 카드로 결제
5. `/success.html` 에서 "결제가 끝났습니다" 가 뜨는지
6. 앱으로 돌아가 **다섯 갈래와 신년운세가 다 열렸는지**
7. **궁합** 으로 가서 여전히 잠겨 있는지 (별도 상품이므로)
8. 궁합 1,900원 결제 → 열리는지
9. 결제 중간에 **취소** 눌러 `/fail.html` 이 제대로 뜨는지

다 되면 `live_ck_` / `live_sk_` 로 바꾸고 Redeploy 하세요.

> 실제 키로 바꾼 뒤에는 **본인 카드로 4,900원 한 번 결제해 보시길** 권합니다.
> 되는 걸 확인하고 환불하시면 됩니다.
